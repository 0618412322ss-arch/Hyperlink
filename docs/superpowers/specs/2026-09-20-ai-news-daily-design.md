# AI 资讯日报网站设计规格

## 1. 项目目标

建设一个公开访问、每天自动更新的中文 AI 资讯网站。系统从免费且公开可访问的渠道采集内容，完成去重、核验和提炼后，每天发布 5–8 条精选资讯。每条内容按时间、背景、核心内容、来源渠道和核验依据整理。

首期不追求覆盖互联网中的所有 AI 消息；优先保证来源透明、信息准确和更新失败时不发布错误内容。

## 2. 发布与运行方式

- 使用 GitHub Pages 托管公开静态网站。
- 使用 GitHub Actions 每天执行一次采集、核验、摘要和发布任务。
- 所有采集数据、来源配置、生成结果和网页代码保存在同一个 GitHub 仓库中。
- 使用免费公开来源与开源依赖，不接入收费数据接口。
- 自动任务失败时保留上一次成功发布的页面，并在页面显示真实的最后更新时间。

## 3. 信息源范围

### 3.1 优先官方来源

- OpenAI 官方博客、新闻与研究页面
- Google / Google DeepMind 官方博客与研究页面
- Microsoft 官方博客、研究与 AI 新闻页面
- Anthropic 官方新闻与研究页面
- 百度、百度智能云、文心相关官方新闻页面
- 腾讯、腾讯研究院、腾讯云与混元相关官方新闻页面

### 3.2 补充公开渠道

- 知乎机构号与可信作者公开文章
- 微博认证机构或企业官方账号公开内容
- 微信公众号可被公开检索和访问的文章
- 可免费访问的权威媒体或研究机构文章

知乎、微博、微信公众号受登录、反爬、搜索可见性和页面结构变化影响，系统只对公开可访问内容做尽力覆盖，不承诺完整或实时收录。

## 4. 每日处理流程

1. 每天定时抓取各来源最近 48 小时的候选内容。
2. 标准化标题、发布时间、作者或发布主体、正文摘要、原始链接和渠道类型。
3. 排除无法确认日期、发布主体或原始出处的候选内容。
4. 通过标题、关键实体、事件关键词和规范化链接进行聚类去重。
5. 执行来源核验并记录核验依据。
6. 按时效性、影响力、可靠度和渠道多样性评分。
7. 从通过核验的候选中选出 5–8 条，生成结构化中文摘要。
8. 验证输出数据格式和链接后，生成静态页面并发布。

系统不得编造缺失事实。自动摘要仅能使用已采集来源中明确出现的信息；存在冲突时应标为“信息存在差异”并退出每日精选。

## 5. 核验规则

每条进入每日精选的资讯必须满足以下条件之一：

- 存在可访问、主体明确、时间明确的官方原始来源；
- 不存在可访问的官方原文，但至少存在两个相互独立且关键事实一致的可靠来源。

核验记录包含：

- 核验状态：已核验或待核验
- 主来源名称与链接
- 辅助来源名称与链接（如适用）
- 原文发布时间
- 系统核验时间
- 简短核验说明

只有“已核验”内容可进入当天 5–8 条精选。“待核验”内容可以保存在内部候选数据中，但不在公开首页展示。

## 6. 内容结构

每条公开资讯包含：

- 标题
- 发布时间
- 背景：事件发生前需要了解的上下文
- 核心内容：简洁说明发生了什么
- 影响：说明值得关注的原因，不能作无来源的推测
- 来源渠道和发布主体
- 核验状态与核验说明
- 原文链接和辅助核验链接
- 分类与涉及机构标签

每天输出 5–8 条。如果当天通过核验的高质量内容不足 5 条，允许少于 5 条，并显示“今日通过核验的资讯较少”，不得用低可信内容补足数量。

## 7. 页面与交互

### 7.1 首页

- 顶部显示站名、最后更新时间、当日通过核验数量和每日更新状态。
- 当天最重要的一条内容作为主报道，以大号标题和简要背景突出展示。
- 其余内容使用杂志式卡片排列。
- 每张卡片均显示时间、摘要、来源和“已核验”标识。

### 7.2 筛选与详情

- 支持按全部、国际、国内、官方发布和行业动态筛选。
- 支持按机构或平台筛选，包括 OpenAI、Google、Microsoft、Anthropic、百度、腾讯、知乎、微博和微信公众号。
- 点击资讯后展开核验依据、相关来源和收录理由。
- 筛选与展开功能在桌面和移动端均可用，并支持键盘操作。

### 7.3 历史与透明说明

- 支持按日期查看历史日报。
- 页脚说明采集范围、核验标准、更新时间和渠道覆盖限制。
- 所有外部来源链接明确标识并在新窗口打开。

## 8. 视觉规范

- 整体为高级黑白编辑部风格，强调可信、克制和可读性。
- 使用象牙白背景、近黑正文、灰阶层次和一种低饱和强调色表示核验状态。
- 标题使用高对比度衬线字体，正文使用现代无衬线字体。
- 使用细线分隔、大留白、非对称网格和克制的进入动画。
- 不使用霓虹渐变、发光按钮或模板化后台仪表盘风格。
- 页面满足常见可访问性要求，包括清晰焦点态、足够对比度、语义化结构和减少动态效果偏好。

## 9. 数据与代码边界

系统拆分为以下独立模块：

- 来源配置：定义来源名称、类型、抓取地址和解析规则。
- 采集器：获取公开页面或 RSS，保存候选内容。
- 标准化与去重：输出统一字段并合并重复事件。
- 核验器：按来源等级与交叉来源规则生成核验记录。
- 编辑器：评分并选出每日 5–8 条，生成结构化摘要。
- 数据输出：保存按日期组织的 JSON 数据和索引。
- 前端：读取静态 JSON，完成展示、筛选、详情和历史浏览。
- 自动化任务：每天运行流程，校验成功后提交并发布新版本。

各模块以明确的 JSON 数据结构通信，单一来源解析失败不得阻塞其他来源。

## 10. 错误处理与安全边界

- 请求失败采用有限次数重试和超时，不无限循环。
- 单一来源异常只记录错误，不中断整批任务。
- 页面结构变化导致解析字段缺失时，该条内容不得进入公开数据。
- 生成数据必须通过结构校验、日期校验、链接协议校验和重复项检查。
- 发布前必须确认至少一条已核验内容；否则保留上一版本并记录失败原因。
- 不绕过登录、验证码、付费墙或平台访问控制，不保存用户凭据和非公开内容。
- 对外部正文只做必要的事实摘要，不复制整篇受版权保护内容。

## 11. 测试与验收

### 自动测试

- 来源解析器使用固定样本测试关键字段提取。
- 去重逻辑测试同一事件不同标题与不同链接的合并。
- 核验规则测试官方单源、双独立来源、来源冲突和缺失日期等情形。
- 输出数据执行 JSON 结构、链接、日期、数量和重复项校验。
- 前端执行构建检查、响应式检查和基础可访问性检查。

### 上线验收

- 网站可通过公开 URL 访问。
- 首页展示真实采集并通过核验的 5–8 条资讯，或在合格内容不足时如实减少数量。
- 每条内容均具有时间、背景、核心内容、来源渠道和核验依据。
- 筛选、详情展开和历史浏览可正常使用。
- 桌面端与手机端布局完整，无明显溢出或不可操作区域。
- 每日自动任务可成功运行；失败时不会覆盖最后一个有效版本。

## 12. 首期范围外事项

- 不提供用户注册、评论、收藏或个性化推荐。
- 不使用收费搜索、媒体监测或社交平台 API。
- 不承诺完整抓取知乎、微博和微信公众号的全部内容。
- 不自动发布无法核验的爆料、传言或匿名消息。
- 不在首期实现分钟级实时更新。
